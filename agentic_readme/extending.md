# Extending immuneML (new components, data model, tests)

Paths are relative to `immuneML/`. The official guides are in `docs/source/developer_docs/how_to_add_new_{encoding,ML_method,report,preprocessing}.rst`, and their example code is in `docs/source/developer_docs/example_code/`. Checker scripts: `scripts/check_new_encoder.py` and `scripts/check_new_ml_method.py`.

## Discovery details
The basic rules and the folder for each kind are in `AGENTS.md`. In addition, `util/ReflectionHandler.py` requires that:
- the class name is unique within its folder;
- the class subclasses the base class for its kind (table below).

If an optional dependency fails to import, the class is skipped and only a warning is logged. For encoders, the defaults file name drops the `Encoder` suffix before converting to snake case.

## Base classes

| Kind | Base class | Main methods to implement |
|---|---|---|
| Encoder | `encodings/DatasetEncoder.py` | `build_object(dataset, **params)` (dispatch on dataset type), `encode(dataset, EncoderParams) -> Dataset` with `encoded_data` set |
| Classifier | `MLMethod.py` (or `SklearnMethod.py` for sklearn wrappers) | `_fit`, `_predict`, `_predict_proba`, `store`, `load`, `get_params`, `can_predict_proba`, `can_fit_with_example_weights`, `get_compatible_encoders`. Do not override `fit` / `predict`. |
| Clustering | `ClusteringMethod.py` | `fit`, `predict`, `fit_predict`, `transform` |
| Dimensionality reduction | `DimRedMethod.py` | fit / transform, `get_dimension_names` |
| Generative model | `GenerativeModel.py` | `fit`, `generate_sequences`, p_gen methods, `save_model`, `load_model` |
| Preprocessing | `Preprocessor.py` | `process_dataset`, `keeps_example_count`, `check_dataset_type` |
| Report | the category base (e.g. `DataReport`, `MLReport`) | classmethod `build_object(**kwargs)`, `_generate() -> ReportResult`; optional `check_prerequisites` |
| Importer | `DataImport.py` (class `<Format>Import`) | usually only `preprocess_file` |
| Example weighting | `ExampleWeightingStrategy.py` | `build_object`, `compute_weights` |

**What each report category receives** (set as attributes before `_generate` is called):

| Report category | Inputs |
|---|---|
| DataReport | `dataset` |
| EncodingReport | `dataset`, already encoded |
| MLReport | `train_dataset`, `test_dataset`, `method`, `label`, `hp_setting` |
| TrainMLModelReport | `state` |
| ClusteringReport | `state` |
| ClusteringMethodReport | `item` |
| GenModelReport | `dataset`, `model` |
| TrainGenModelReport | `original_dataset`, `generated_dataset`, `model` |
| MultiDatasetReport | `instruction_states` |

Reports return `ReportResult(name, info, output_figures, output_tables, output_text)`. Each output is a list of `ReportOutput(path, name)`. Figures are usually plotly HTML.

## Docstring standard (the docs are generated from it)
See `docs/source/developer_docs/class_documentation_standards.rst`. A component docstring has, in order:
1. a short description;
2. `**Dataset type:**` (for encoders);
3. `**Specification arguments:**` with one `- name (type): description` line per argument;
4. `**YAML specification:**` followed by an indented `.. code-block:: yaml` showing a `definitions:` example.

The documentation is generated by `scripts/specs_docs_generation.py`, which calls `DefinitionParser.generate_docs` and `InstructionParser.generate_docs`.

## Data model essentials (`data_model/`, `environment/`)

**Datasets**
- `RepertoireDataset`: one TSV and one YAML per repertoire, plus a metadata CSV.
- `SequenceDataset` and `ReceptorDataset`: one TSV and one YAML for the whole dataset. A ReceptorDataset stores two rows per receptor, linked by `cell_id`.
- Rows follow the AIRR schema and are held in a bionumpy `AIRRSequenceSet`.
- Useful builders: `build_from_objects`, `Repertoire.build`, `SequenceDataset.build_from_partial_df`.

**Enums** (`SequenceParams.py`, `environment/SequenceType.py`)
- `RegionType`: IMGT_CDR3, IMGT_JUNCTION, FULL_SEQUENCE, …
- `SequenceType`: AMINO_ACID, NUCLEOTIDE.
- `Chain` and `ChainPair`.
- Field names are the region name plus `_aa` for amino acids, e.g. `cdr3_aa`.

**Encoded data:** `EncodedData(examples, labels, example_ids, feature_names, encoding, …)`.

**Labels:** `Label(name, values, positive_class)` and `LabelConfiguration`.

**Trained models:** exported and imported by `IO/ml_method/MLExporter` / `MLImport` as a zip containing `ml_config.yaml`.

## Tests (`test/` at the repository root)
- The test folders mirror the package; `test/integration_tests/` runs complete specs. Most older tests use unittest, newer ones use pytest.
- Always set `os.environ[Constants.CACHE_TYPE] = CacheType.TEST.name`.
- Use the temporary directory `PathBuilder.remove_old_and_build(EnvironmentSettings.tmp_test_path / "<unique>")` and delete it when the test finishes.
- Build test data with `simulation/dataset_generation/RandomDatasetGenerator.generate_{repertoire,receptor,sequence}_dataset(...)`, or construct the objects by hand.
- For an integration test, write a spec dict to YAML and call `ImmuneMLApp(spec_path, result_path).run()`.
